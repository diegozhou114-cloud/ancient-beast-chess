# 联机对战 UX 规范

> 状态：Approved
> 更新日期：2026-08-31
> 作者：Codex（single-agent fallback）
> 流程标识：`OnlinePlayFlow`
> 平台：Web、macOS、Windows
> 无障碍等级：Basic

## 1. 目的

玩家可以连接自己选择的暗兽棋服务器，创建或加入双人房间，并在短暂断线后继续原对局。流程必须让玩家始终知道当前是否连接、自己是哪一方、正在等待什么。

玩家从主页进入时通常还没有房间，目标是在不理解服务器内部概念的前提下，用一个地址和一个房间码开始对局。情绪目标是明确、可控，不因等待或断线怀疑操作是否生效。

## 2. 范围

包含：自定义服务器地址、建房、加入、双方准备、权威棋局、认输、主动离房、自动重连。

不包含：账号、自动匹配、房间列表、聊天、观战、排行榜、跨设备恢复、服务发现。

## 3. 导航

```text
主页
  ├── 人机设置 -> 人机棋局
  └── 联机大厅
        ├── 创建房间 -> 等待/准备 -> 联机棋局 -> 结果
        ├── 加入房间 -> 等待/准备 -> 联机棋局 -> 结果
        └── 恢复上次席位 -> 等待或联机棋局
```

## 4. 页面结构

```text
联机对战
  服务器地址 [________________]
  连接状态   未连接 / 连接中 / 已连接 / 正在重连

  [创建房间]

  房间码 [______] [加入房间]
  [恢复上次房间，仅存在会话凭据时显示]

进入房间后
  房间码 ABC234   本方 朱/墨
  朱方状态        墨方状态
  [准备/取消准备] [离开房间]
```

桌面端保持与人机设置页相同宽度；移动端所有输入和命令纵向排列。房间状态不使用浮动卡片，沿用现有上下分隔线布局。

组件清单：服务器地址输入、创建按钮、房间码输入、加入按钮、恢复按钮、连接状态、房间码显示、双席位状态、准备按钮和离开按钮。没有会话时显示连接表单；有会话但快照尚未到达时显示连接状态，不显示空棋盘。

## 5. 状态与行为

| 状态 | 玩家可做什么 | 系统行为 |
|---|---|---|
| 未连接 | 修改地址、建房、加入、恢复 | 不建立网络连接 |
| 连接中 | 返回主页 | 禁用重复命令 |
| 等待对手 | 复制房间码、离开 | 保持连接并显示席位 |
| 等待准备 | 准备/取消准备、离开 | 两方准备后自动进入棋局 |
| 对局中 | 执行本人回合行动、认输 | 每步携带最新版本号 |
| 正在重连 | 返回主页 | 棋盘保持可见但锁定操作 |
| 已结束 | 返回主页、返回联机大厅、再开一房 | 清除旧重连凭据 |

## 6. 输入与焦点

- 键盘顺序：服务器地址、创建房间、房间码、加入房间、恢复房间、返回主页。
- 进入房间后顺序：复制房间码、准备/取消准备、离开房间。
- 进入棋局后焦点遵循现有顶栏和 4×5 棋盘 DOM 顺序。
- 鼠标和触控使用相同按钮；本项目没有游戏手柄输入系统，本次不新增。

## 7. 数据与事件

| 数据 | 来源与更新 | 空值处理 |
|---|---|---|
| 服务器地址 | 玩家输入；仅本地保存最近输入 | 使用本机默认地址 |
| 房间码、阵营、令牌 | `room_joined` | 未加入时隐藏；令牌永不显示 |
| 席位、准备、棋局、结果 | 服务器 `snapshot`，每次消息替换 | 快照前显示连接中 |
| 连接状态 | WebSocket 生命周期 | 断线显示正在重连 |

玩家命令只发送 `create_room`、`join_room`、`resume`、`ready`、`action`、`resign` 和 `leave_room`。UI 不创建或修改联机棋局状态。

## 8. 重连

- 成功进入房间后，将服务器地址、房间码、阵营和重连令牌写入 `sessionStorage`。
- 意外关闭连接后以短间隔自动重连；恢复期间不允许行棋。
- 页面刷新后在联机大厅显示“恢复上次房间”，不自动访问外部服务器。
- 主动离房、认输后返回主页或房间失效时清除凭据。

## 9. 错误

- 地址无法解析：请检查服务器地址。
- 连接失败：无法连接服务器，请检查地址和服务器状态。
- 房间不存在或已满：保留输入，允许立即重试。
- 重连令牌失效：清除旧会话，返回联机入口。
- 陈旧行动：等待下一份快照，不重复执行原行动。

所有错误都不显示原始令牌、连接标识或服务器内部堆栈。

## 10. 转场与文本

- 页面切换沿用现有即时显隐，不新增动画；重连不离开棋盘。
- `role="status"` 宣布连接与等待状态，`role="alert"` 宣布错误。
- 状态短句最多 24 个汉字；按钮最多 8 个汉字；错误最多 36 个汉字。窄屏允许换行，不截断关键错误。
- 颜色状态必须同时带文字或符号。所有命令使用原生按钮禁用语义。

## 11. 入口与出口

| 入口 | 目的地 | 携带数据 |
|---|---|---|
| 主页“联机对战” | 联机大厅 | 最近服务器地址、可恢复会话标记 |
| 建房/加入/恢复成功 | 房间等待区 | 房间码、阵营、公开快照 |
| 两方准备 | 联机棋局 | 最新公开棋局快照 |

| 出口 | 目的地 | 行为 |
|---|---|---|
| 未进房返回 | 主页 | 关闭连接 |
| 等待中离开 | 联机大厅或主页 | 发送 `leave_room` 并清除会话 |
| 对局中认输/返回 | 结果或主页 | 发送 `resign` 并清除会话 |
| 结果后再开一房 | 新等待区 | 新连接并创建新房间 |

## 12. 验收标准

- 两个独立客户端可完成建房、加入、准备、至少一次翻子和认输。
- 双方棋盘、回合、日志和结果保持一致，未翻棋子不含阵营或类型。
- 等待房间主动离开后立即释放席位。
- 对局中断线可自动恢复，恢复期间棋盘不可操作。
- 客户端包和源码不包含任何用户提供的公网地址或凭据。
- 人机模式原有流程和五档难度不回归。
- 连接命令在正常本机网络下 2 秒内进入下一状态或显示错误。
- `1440×900` 与 `390×844` 下无横向溢出、遮挡或不可见命令。
